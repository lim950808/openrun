# ADR-0001 1차 범위 축소: 8주 안에 리포트가 매주 나오는 상태

- 상태: 승인
- 날짜: 2026-11-09
- 관련: [로드맵](../roadmap.md), 리서치 01·02

## 맥락

첫 로드맵 초안은 1차 완성에 약 3개월, 전체 6개월이었다. 이직 일정상 "다 만들고 보여주는" 포폴은 늦고, 중간 상태에서 보여줄 것이 없다. 또한 리서치 결과 좌석 임시배정 + 대기열 토큰 + Outbox 수준의 Kotlin 포폴은 이미 포화 영역이라, 기능 개수보다 "숫자로 증명된 개선 이력"이 차별점이 된다.

## 결정

1차 목표를 "8주 안에 주간 오픈런 리포트가 자동으로 나오는 상태"로 바꾼다. 첫 리포트는 1차 끝이 아니라 M1 좌석 선점이 끝나는 3주차(2026-11-29)에 수동으로 발행한다.

**1차 포함**
- M1 좌석 선점: DB 락 3종과 Redis Lua hold TTL 비교
- M2 최소 대기열: ZSET 순번, 입장 토큰, 입장 속도 제어, 폴링
- M3 결제 핵심: 토스 confirm, 금액 검증, 멱등키, hold TTL ↔ 10분 승인창 정합, 웹훅 inbox, 예약·결제 상태머신 분리
- 최소 화면 3장, 주간 오픈런 자동화

**1.5차로 이동**
- 취소수수료 정책과 부분취소
- 대기자 승계(hold 체인)
- janitor 3경로 확장
- 봇 탐지 고도화(Turnstile/ALTCHA, 디바이스 지문)
- 디자인 토큰 정리, 식당 시간 슬롯 모델

**2차 이후로 이동**
- 측정 파이프라인(CDC → 마트 → 리니지), AI 브리핑과 평가 하네스

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 1차에 취소·대기자 승계까지 포함(원안) | 12주 이상 소요. 그동안 보여줄 숫자가 없음 |
| 결제를 2차로 미루고 예약만 1차 | 친구 레포와의 차별점인 "hold ↔ 승인창 정합"이 1차에서 빠짐 |
| 화면 없이 API만 1차 | 프로덕트 서사가 사라지고 리포트에 보여줄 UX 상태가 없음 |

## 결과

- 좋아지는 것: 3주차부터 매주 숫자가 쌓인다. 개선 이력이 곧 블로그와 면접 자료가 된다.
- 감수하는 것: 1차 결제는 전액 취소만 지원한다. 대기열은 폴링만, SSE는 나중. 화면은 디자인 시스템 없이 최소 토큰만.
- 다시 검토할 조건: 3주차 리포트가 발행되지 못하면 M1 범위를 더 줄인다(Redis Lua 비교를 4주차로).

## 증명

- 2026-11-29 리포트 #1 발행 여부
- 2027-01-03 기준 cron에 의한 자동 발행 여부
- 리포트 간 지표 변화 로그(오버셀, p99, 전환율)
